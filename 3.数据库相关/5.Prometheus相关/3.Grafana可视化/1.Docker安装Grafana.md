本文介绍如何通过`Docker`快速部署`Grafana`服务，并将其与`Prometheus`数据源进行对接，实现监控数据的可视化展示。

`Grafana`是一款开源的数据可视化和监控分析平台，支持对接`Prometheus`、`Elasticsearch`、`InfluxDB`等多种数据源，通过丰富的图表面板将监控指标以直观的方式呈现出来。

首先，在宿主机上创建配置目录和数据目录，用于持久化存储`Grafana`的配置文件和数据库数据：

```bash
mkdir -p /opt/grafana/config
mkdir -p /opt/grafana/data
```

创建完成后，建议为`data`目录赋予`777`权限，避免容器内用户因权限不足而无法写入数据：

```bash
chmod 777 /opt/grafana/data
```

使用以下命令拉取最新版本的`Grafana`镜像：

```sh
docker pull grafana/grafana:latest
```

创建并启动`Grafana`容器：

```bash
docker run -d \
  --name grafana \
  -p 3000:3000 \
  -v /opt/grafana/data:/var/lib/grafana \
  -e GF_SECURITY_ADMIN_PASSWORD=admin123 \
  grafana/grafana:latest
```

上述启动参数的含义如下：

- `-p 3000:3000`：将宿主机的`3000`端口映射到容器的`3000`端口，`Grafana`的`Web UI`默认通过该端口提供服务。
- `-v /opt/grafana/data:/var/lib/grafana`：将宿主机的`/opt/grafana/data`目录挂载到容器内的`/var/lib/grafana`目录。`Grafana`的`SQLite`数据库、插件、告警状态等数据均存储在该路径下，挂载后可实现数据持久化，容器重建后配置和仪表盘不会丢失。
- `-e GF_SECURITY_ADMIN_PASSWORD=admin123`：通过环境变量预设管理员`admin`账号的登录密码为`admin123`。若省略该变量，`Grafana`首次启动时会使用默认密码`admin`，并在首次登录时强制要求修改。

执行上述命令后，可以通过以下命令查看容器状态：

```bash
docker ps | grep grafana
```

打开浏览器，访问`http://<server-ip>:3000`。如果能正常显示`Grafana`登录页面，则说明安装成功：

`Grafana`部署完成后，需要添加`Prometheus`作为数据源，才能将监控数据可视化展示。点击页面左侧的「齿轮图标」→「`Data sources`」，然后点击「`Add data source`」按钮：

![image-xxxxxx](image/image-xxxxxx.png)

在数据源类型列表中选择「`Prometheus`」：

![image-xxxxxx](image/image-xxxxxx.png)

进入`Prometheus`数据源配置页面后，在「`Connection`」区域的「`Prometheus server URL`」输入框中填入`Prometheus`的访问地址，例如`http://192.168.64.3:9090`。如果`Prometheus`和`Grafana`运行在同一台宿主机上，且`Prometheus`使用宿主机网络或已映射端口，则使用宿主机的实际`IP`地址，而不是`localhost`：

![image-xxxxxx](image/image-xxxxxx.png)

`localhost`在每个容器内部都指向自身的本地回环接口，且各容器的网络命名空间相互隔离。因此，`Grafana`容器内访问`localhost:9090`时，只会访问自身，无法直接访问`Prometheus`容器。如果希望容器间通过名称通信，可以创建自定义`bridge`网络，将`Grafana`和`Prometheus`接入同一网络，通过容器名进行`DNS`解析。

配置完成后，滚动到页面底部，点击「`Save & test`」按钮。如果配置正确，会显示绿色的「`Successfully queried the Prometheus API`」提示：

数据源添加成功后，就可以创建仪表盘（`Dashboard`）来可视化展示`Prometheus`采集的监控指标。点击页面左侧的「四个方块图标」→「`Dashboards`」，然后点击「`New`」→「`New dashboard`」：

点击「`Add visualization`」按钮，选择刚才添加的`Prometheus`数据源，然后在查询框中输入`PromQL`表达式，例如`up`，即可看到对应的监控数据图表：

`Grafana`支持通过环境变量对服务进行灵活配置，以下是几个常用的环境变量：

| 环境变量 | 作用 | 默认值 |
| --- | --- | --- |
| `GF_SECURITY_ADMIN_PASSWORD` | 设置`admin`账号的初始密码 | `admin` |
| `GF_SECURITY_ADMIN_USER` | 设置管理员账号的用户名 | `admin` |
| `GF_SERVER_HTTP_PORT` | 修改`Grafana`的`HTTP`服务端口 | `3000` |
| `GF_SERVER_ROOT_URL` | 配置外部访问`Grafana`的根`URL`，用于反向代理场景 | `%(protocol)s://%(domain)s:%(http_port)s/` |
| `GF_INSTALL_PLUGINS` | 启动时自动安装的插件列表，多个插件用逗号分隔 | 无 |

例如，如果需要同时修改服务端口并自动安装`Clock`插件，可以在启动命令中追加以下环境变量：

```bash
  -e GF_SERVER_HTTP_PORT=8080 \
  -e GF_INSTALL_PLUGINS=grafana-clock-panel \
```

除了环境变量外，`Grafana`也支持通过挂载自定义的`grafana.ini`配置文件进行更细粒度的配置。在宿主机创建配置文件：

```bash
vim /opt/grafana/config/grafana.ini
```

编辑完成后，在启动命令中追加以下挂载参数：

```bash
  -v /opt/grafana/config/grafana.ini:/etc/grafana/grafana.ini \
```

即可使自定义配置生效。当同时存在环境变量和配置文件时，环境变量的优先级高于配置文件中的同名配置项。
