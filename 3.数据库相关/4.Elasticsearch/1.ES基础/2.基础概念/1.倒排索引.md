在学习`Elasticsearch`之前，首先需要了解正排索引和倒排索引的概念。

### 一、正排索引

正排索引是一种将文档编号映射到文档内容的数据结构。每篇文档都有一个唯一的编号，可以是整数或其他形式的标识符。通过文档编号，正排索引能够快速获取对应的文档内容，适用于需要根据文档编号检索或展示完整文档内容的场景。

假设有以下五个文档：

| 文档编号 | 文档内容                                                     |
| -------- | ------------------------------------------------------------ |
| `1`      | 数据库是管理数据的基础组件，能够高效地存储和检索数据，确保数据的安全性和一致性。 |
| `2`      | 高效的数据处理系统不仅可以支持大规模的数据存储，还能进行复杂的数据分析和实时处理。 |
| `3`      | 数据库通常需要通过各种技术手段优化查询性能，以显著提高数据检索的速度和效率。 |
| `4`      | 大数据技术涵盖了数据存储、处理、分析和挖掘等多个方面，帮助从海量数据中提取有价值的信息。 |
| `5`      | 数据库和大数据技术的有效结合能够实现更高效的数据处理和深入的分析，为决策提供更强大的支持。 |

通过文档编号，可以直接、迅速地获取相应的文档内容。

### 二、倒排索引

倒排索引以词汇为核心，记录每个词汇对应的文档列表，以及该词汇在各文档中的出现位置。通过倒排索引，搜索引擎可以根据用户输入的关键词，快速定位包含这些关键词的文档。仍以上述五个文档为例，其倒排索引可以表示为：

| 词项   | 文档编号                |
| ------ | ----------------------- |
| 数据库 | `1`、`3`、`5`           |
| 数据   | `1`、`2`、`3`、`4`、`5` |
| 高效   | `1`、`2`、`5`           |
| 存储   | `1`、`2`、`4`           |
| 处理   | `2`、`4`、`5`           |
| 分析   | `2`、`4`、`5`           |
| 大规模 | `2`                     |
| 技术   | `3`、`4`、`5`           |
| 结合   | `5`                     |
| 支持   | `2`、`5`                |

通过倒排索引，可以快速定位包含指定关键词的文档。对于包含多个词项的查询，系统会分别获取每个词项对应的文档集合，再对这些集合进行交集运算，最终返回同时包含所有查询词项的文档。例如：

- 搜索「技术 支持」时，词项「技术」的文档集合是`{3, 4, 5}`，词项「支持」的文档集合为`{2, 5}`，所以取交集为词项`5`。
- 搜索「存储 处理」时，词项「存储」的文档集合是`{1, 2, 4}`，词项「处理」的文档集合是`{2, 4, 5}`，取交集为文档`{2, 4}`。

倒排索引不仅记录词项对应的文档编号，还可以记录词项在文档中的出现位置。记录词项出现位置的倒排索引也称为带位置的倒排索引（`Positional Index`）。假设某文档经过分词后得到以下词项序列：

```
数据库(0) / 支持(1) / 高效(2) / 数据(3) / 存储(4) / 数据(5) / 检索(6)
```

在这里，词项「数据」出现在该文档经过分词后生成的词项序列中的第`3`和第`5`个位置。通过记录这些位置信息，搜索引擎能够支持短语查询和邻近查询，而不仅仅是判断文档是否包含指定词项。

对于英文文本，由于单词之间通常使用空格或标点符号分隔，因此可以基于这些分隔符进行简单切分。但在实际处理中，还需要考虑词干化（`stemming`）和词形还原（`lemmatization`）等技术，将不同形式的单词转换为其基本形式，从而提高文本匹配的准确性。

中文文本与英文不同，词语之间通常不存在明确的分隔符，因此需要借助中文分词工具（如`jieba`）将文本切分为具有独立语义的词语。此外，分词过程中还需要进行停用词处理，停用词是搜索引擎通常会忽略的高频常用词，例如「的」、「是」、「在」等。由于这类词对检索结果的贡献较低，通常会在构建倒排索引时进行过滤，以减少索引体积并提高检索效率。

关键词匹配并不局限于完全一致的文本匹配。例如，搜索「内存」时，也可以匹配包含「内存管理」的文档。此外，还可以结合模糊匹配、同义词扩展和词干提取等技术，进一步优化检索效果，提高搜索系统的召回能力。
