现代计算机硬件包括`CPU`、`GPU`、内存、显存、硬盘等不同设备，它们的底层都建立在现代半导体技术之上。

可以记住一条核心链路：高纯度硅 → 晶圆 → 晶体管 → 集成电路 → 芯片 → 硬件设备。

硅是一种重要的半导体材料，制造芯片使用的是经过高度提纯并加工形成的单晶硅，再切割成薄片，也就是晶圆。芯片制造的本质，就是在晶圆上通过光刻、刻蚀、沉积等工艺，构建数量极其庞大的微小电子结构，其中最核心的器件就是晶体管。

晶体管可以简单理解为能够高速控制电流的微型电子开关，通过控制电流状态表示数字电路的`0`和`1`。大量晶体管按照特定方式连接，可以构成逻辑电路和存储电路，最终形成`CPU`、`GPU`、`DRAM`、`NAND Flash`等不同类型的芯片。这些芯片通过不同的电路组织方式实现对应功能，`CPU`擅长通用计算，`GPU`擅长大规模并行计算，`DRAM`用于临时存储数据，`NAND Flash`用于长期保存数据。

需要注意的是，芯片和硬件设备并不完全等价。一颗`CPU`或`GPU`本身就是芯片，而内存条、显卡、`SSD`通常是由多种芯片和其他电子元件组合而成的完整硬件设备。例如，显卡通常包含`GPU`芯片和显存芯片，`SSD`通常包含`NAND Flash`芯片和主控芯片。

`CPU`和`GPU`的核心差异可以用一句话概括：`CPU`像少量能力很强的专家，每个人都可以独立处理复杂且变化多的任务；`GPU`像一支规模庞大的标准化作业团队，每个成员执行能力相对简单，但可以同时处理大量相似的数据，从而获得极高的整体吞吐。

`CPU`的设计目标是以低延迟处理复杂且多变的串行任务。它通常拥有数量较少但功能强大的核心，每个核心都配备相对复杂的控制单元和较大容量的缓存，擅长分支预测、乱序执行以及复杂的逻辑判断。一个`CPU`核心通常还可以通过`SMT`（同时多线程）机制同时维护多个硬件线程。例如，一个核心可以同时运行`2`个硬件线程，因此操作系统看到的逻辑`CPU`数量会多于实际的物理核心数量。在编写后端业务接口、处理请求路由或操作数据库时，相关代码最终都需要由`CPU`执行。

> 以下`SM`、`Warp`、`Thread Block`等概念主要以`NVIDIA GPU`的架构和`CUDA`编程模型为例。

`GPU`的设计目标是利用高吞吐的并行计算能力，高效处理大量简单且同构的计算任务。它由几十到上百个`SM`（流式多处理器）组成，每个`SM`包含几十到上百个计算核心，并通过`Thread Block`（线程块）和`Warp`（线程束）组织与调度大量线程执行。单个`SM`的驻留线程数量通常是其计算核心数量的`12～32`倍。因此，一块拥有数千个计算核心的`GPU`可以同时管理数万甚至数十万个线程。

其中，一个`Thread Block`所包含的线程数量由程序配置决定，同时受到`GPU`硬件资源的限制。实际开发中，常见的配置包括`128`、`256`、`512`等线程。`Warp`则是`Thread Block`内部进一步划分出的线程执行组，在`NVIDIA GPU`中，一个`Warp`通常包含`32`个线程。`Thread Block`是程序员组织线程及实现任务协作的基本单位，而`Warp`则是`NVIDIA GPU`硬件进行线程调度与执行的重要单位。一个`Warp`中的`32`个线程遵循`SIMT`（单指令多线程）模型执行相同的指令，同时处理不同的数据。

从架构层面看，`CPU`为了降低单线程延迟，会将大量晶体管用于缓存、分支预测、乱序执行以及复杂的控制逻辑，并结合`SMT`机制，尽可能提升单个核心的硬件利用率。相比之下，`GPU`更加注重并行吞吐，将更多晶体管分配给计算单元；它并不依赖高成本的单线程延迟优化，而是通过大规模硬件多线程来隐藏内存访问延迟。

`GPU`并不是将所有线程都独立分发给具体的计算核心，而是以线程块为单位分发至各个`SM`，再由`SM`内部的调度器完成`Warp`级线程调度与切换，从而在有限的计算资源上实现分时复用。同时，`GPU`的性能不仅取决于峰值计算能力，还高度依赖显存带宽。只有持续、高效地向计算单元供给数据，才能充分释放计算吞吐，避免计算资源因数据供给不足而处于空闲状态。

传统独立`GPU`的一个重要硬件特征，是拥有与系统内存相互分离的显存体系。`CPU`主要使用主机内存（`Host Memory`），即系统内存；独立`GPU`则拥有自己的设备内存（`Device Memory`），通常表现为显存。`GPU`计算所需的数据通常需要从主机内存传输到设备内存，然后由`GPU`计算单元从本地显存及片上缓存等存储层级中读取和处理。由于`GPU`包含大量并行计算单元，需要持续获取大量数据，因此本地显存通常能够提供远高于跨设备访问的有效带宽，有利于维持较高的计算吞吐。

`GPU`并非完全无法访问主机内存。在特定硬件、驱动和编程模型下，可以通过相应机制直接或间接访问主机内存。但与访问本地显存相比，访问主机内存通常具有更高的延迟和更低的有效带宽。如果计算过程中频繁在主机内存与设备内存之间传输大量数据，就可能形成性能瓶颈，使部分计算单元因等待数据而处于空闲状态。因此，在典型的`GPU`计算场景中，通常会尽可能让计算所需的数据驻留在`GPU`本地显存中，以减少跨设备数据传输，从而充分发挥`GPU`的并行计算能力。

> 需要注意的是，上述描述主要针对传统独立`GPU`。集成`GPU`通常可以与`CPU`共享系统内存，因此不能笼统地认为所有`GPU`都拥有与`CPU`物理分离的设备内存。

`CPU`与`GPU`的核心区别可以归纳为以下几个核心维度：

| 对比维度   | `CPU`                                | `GPU`                                      |
| ---------- | ------------------------------------ | ------------------------------------------ |
| 核心目标   | 低延迟，快速完成单个复杂任务         | 高吞吐，同时完成大量相似任务               |
| 核心数量   | 少量强大的计算核心                   | 大量相对简单的计算资源                     |
| 单核心能力 | 强，擅长复杂控制和逻辑判断           | 相对简单，更强调批量计算                   |
| 并行方式   | 多核、`SMT`等方式进行并行            | 大量线程通过`Thread Block`、`Warp`组织执行 |
| 擅长任务   | 分支多、逻辑复杂、任务变化大的程序   | 数据量大、计算规则相同、容易并行的程序     |
| 内存特点   | 更依赖缓存降低访问延迟               | 更依赖高显存带宽持续供给数据               |
| 典型应用   | 操作系统、后端服务、数据库、业务逻辑 | 图形渲染、深度学习、矩阵计算、科学计算     |

需要注意的是，`GPU`并不是在所有场景下都比`CPU`快，`GPU`的优势建立在任务具有较高数据并行性的前提下。如果一个任务包含大量分支判断、复杂控制逻辑、强数据依赖、频繁的随机内存访问，或者任务规模较小、`CPU`与`GPU`之间的数据传输成本较高，那么`GPU`的并行计算能力可能无法得到充分利用，甚至可能不如`CPU`。简单来说，`CPU`更适合低延迟、复杂且多变的任务，而`GPU`更适合计算规则相对统一、数据规模较大且能够高度并行的任务。
